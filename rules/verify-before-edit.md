# 既存ファイル修正前の確認規約

## Overview

AI は「これが原因ではないか」という憶測でファイルを即修正する癖がある。
これは別のバグを生み、根本原因を隠蔽する最悪の対処になる。
**根拠を得てから手を動かす**を鉄則とする。

## 修正前に行うこと

原因が不明な状態でのコード変更を禁止する。以下の順で対処すること。

```
① 公式ドキュメント・リリースノートを確認する
      ↓ それでも不明なら
② Web 検索で事例を確認する
      ↓ それでも不明なら
③ デバッグログを仕込んで実際の動作を観測する
      ↓ 根本原因が特定できてから
④ 修正を行う
```

**ログを仕込む前に修正してはならない。**
「おそらくここが問題」という推測だけで変更を加えることを禁止する。

## Common Mistakes

**Bad: 憶測で即修正**
```
# エラーログを見て「タイムアウトかも」と思い、即 timeout 値を変更する
# → 実際の原因は別の箇所だったが、変更が原因を隠した
```

**Good: ログで確認してから修正**
```
# まずデバッグログを追加して実際の応答時間を計測
# → タイムアウトではなく Lambda のコールドスタートと判明
# → 適切な対処（Provisioned Concurrency）を選択できた
```
